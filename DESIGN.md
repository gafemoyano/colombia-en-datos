# Design System: Colombia en Datos

## Overview

**Creative North Star: "The Statistical Desk"**

The Statistical Desk is an analytical workspace: calm enough for sustained reading, methodical enough for audit, and dense enough to keep definitions, evidence, and actions in view. It behaves like a well-kept working surface rather than a presentation layer; every control supports inspection, validation, or movement through a precise workflow.

The system is sober, precise, and trustworthy. Paper-white content surfaces sit on measured slate layers, Survey Blue identifies purposeful action, and Validation Teal confirms evidence without turning status into decoration. Responsive behavior is structural: the admin grid becomes one column below the large breakpoint, navigation labels hide below the small breakpoint, and type remains fixed rather than fluid.

**Key Characteristics:**
- Work-first density with compact controls, explicit labels, and readable tables.
- Quiet tonal layering, fine borders, and minimal ambient shadow.
- Restrained accent use reserved for actions, selection, focus, and state.
- Consistent radii, spacing, icon scale, and operational language across screens.

## Colors

Survey Blue, Paper White, Measured Slate, and Validation Teal form a restrained palette in which state is visible but never ornamental.

### Primary
- **Survey Blue** (`brand-survey-blue`): the brand action color for authored surfaces; its deeper steps support hover and high-contrast emphasis.
- **Semantic Primary** (`primary`): the canonical UI action token used by shared buttons and interactive primitives.

### Secondary
- **Validation Teal** (`brand-validation-teal`): positive validation and trustworthy completion in brand-authored experiences; pair it with text or icon evidence so color never carries status alone.
- **Measured Slate** (`admin-slate-50` through `admin-slate-950`): the admin surface, border, text, and inactive-control vocabulary.

### Tertiary
- **Measured Warmth** (`brand-warm`, `brand-warm-soft`): limited warning or contextual emphasis, never a decorative counter-accent.
- **Semantic Status** (`status-emerald-*`, `status-amber-*`, `status-red-*`, `destructive`): success, warning, error, and destructive consequences with explicit labels.

### Neutral
- **Paper White** (`brand-paper-white`, `background`, `card`, `popover`): the reading and working surface.
- **Measured Ink** (`brand-ink`, `foreground`, `card-foreground`): primary text and high-confidence data.
- **Muted Evidence** (`brand-muted`, `muted-foreground`, `admin-slate-500`): supporting descriptions and metadata, not critical instructions.
- **Quiet Rules** (`brand-border`, `border`, `input`, `admin-slate-200`): one-pixel separation for fields, tables, cards, and dividers.

**The Two-Layer Token Rule.** Brand tokens (`--c-*`) govern authored identity and data-storytelling surfaces; semantic UI tokens (`--background`, `--primary`, `--border`, and their peers) govern reusable controls and shadcn-svelte primitives. On the admin surface, direct Measured Slate utilities are the established local vocabulary. Never substitute one layer merely because two colors look similar; shared components take semantic tokens, while a deliberately branded composition may take brand tokens.

**The Evidence Rule.** Validation Teal, amber, and red always accompany explicit status text, a label, or an icon; color alone never communicates workflow state.

## Typography

**Display Font:** Inter Variable (with sans-serif fallback)
**Body Font:** Inter Variable (with sans-serif fallback)
**Label/Mono Font:** the system monospace stack for indicator codes, frequency codes, dimensions, and pasted schemas only.

**Character:** Inter keeps labels, tables, and instructions neutral and highly legible. Weight and compact scale establish hierarchy; there is no decorative display face and no fluid type.

### Hierarchy
- **Headline** (700, `1.875rem`, 1.2): page titles only, with tight tracking.
- **Title** (600, `1rem`, 1.5): card headings, panel headings, and strong empty-state prompts.
- **Body** (400, `0.875rem`, 1.5): instructions and interface copy; prose columns stay near the observed `max-w-2xl` measure.
- **Label** (500, `0.875rem`, 1): form labels and compact control text.
- **Compact Label** (500, `0.75rem`, `0.025em` when uppercase): table headings, metadata labels, and badges.
- **Code** (400, `0.75rem`, 1.333): machine identifiers and tabular schema examples only.

**The One-Family Rule.** Inter carries every UI role; never introduce a display font into labels, buttons, headings, or data.

**The Code-Is-Data Rule.** Monospace is reserved for literal codes, dimensions, schema fields, and source text; explanatory prose remains Inter.

## Elevation

The system uses quiet tonal layering first: Paper White cards rest on Measured Slate page backgrounds and are defined by one-pixel borders. Ambient shadow is minimal—`shadow-sm` on cards and the admin mark—while `shadow-md` is reserved for floating popovers; dialogs use a subtle foreground ring rather than a heavy drop shadow. Depth must clarify containment or floating state, never decorate a static workflow.

### Shadow Vocabulary
- **Ambient Low** (`0 1px 3px 0 rgb(0 0 0 / 0.1), 0 1px 2px -1px rgb(0 0 0 / 0.1)`): the existing `shadow-sm` treatment for cards and the admin identity mark.
- **Floating Medium** (`0 4px 6px -1px rgb(0 0 0 / 0.1), 0 2px 4px -2px rgb(0 0 0 / 0.1)`): the existing `shadow-md` treatment for popovers only.
- **Overlay Ring** (`0 0 0 1px color-mix(in oklab, var(--foreground) 10%, transparent)`): quiet dialog boundary on top of the overlay.

**The Tonal-First Rule.** Separate static surfaces with background tone and a one-pixel border before adding shadow; if a card appears to float for decoration, remove the shadow.

## Components

**Component philosophy: "Dense enough for work, quiet enough for scrutiny."** Components use familiar affordances, a compact height scale, visible focus, and consistent state language.

### Buttons
- **Shape:** gently compact corners (`rounded-lg`, base `0.625rem`); extra-small and small sizes cap the radius with `rounded-md`.
- **Primary:** semantic primary background and primary foreground, `2rem` default height, `0.625rem` horizontal padding, medium `0.875rem` type.
- **Variants:** default, outline, secondary, ghost, destructive, and link are canonical. Sizes are `xs`, `sm`, default, `lg`, `icon-xs`, `icon-sm`, `icon`, and `icon-lg`.
- **Hover / Focus / Active:** hover changes tone, focus uses a three-pixel half-opacity semantic ring plus focus border, and press moves the control down one pixel when it does not open a popup. Disabled controls block pointer events and use 50% opacity.

### Badges
- **Style:** compact pill (`rounded-full`) with `0.75rem` semibold text and `0.625rem` horizontal padding.
- **Variants:** default, secondary, destructive, warning, success, and outline. Status variants pair quiet tinted backgrounds with explicit status wording.

### Cards / Containers
- **Corner Style:** `rounded-xl` (`0.875rem`) for the admin Card; internal panels and status blocks use `rounded-lg` (`0.625rem`).
- **Background:** white content over slate-50 page tone.
- **Shadow Strategy:** Ambient Low only, backed by a slate-200 border.
- **Internal Padding:** `1.25rem` is the canonical admin card inset; related groups use `1rem` to `1.5rem` gaps.

### Inputs / Fields
- **Style:** `2.5rem` height, white background, slate-200 border, `rounded-md` (`0.5rem`), and `0.75rem` horizontal padding. Select and textarea share the same vocabulary; textarea starts at `6rem` minimum height.
- **Focus:** no default outline; a two-pixel slate-950 ring with a two-pixel white offset makes keyboard focus unmistakable on admin forms. Semantic primitives use the shared ring token.
- **Error / Disabled:** disabled fields use not-allowed cursor and 50% opacity. Errors require an explicit message and red status treatment, never a border alone.

### Navigation
- **Style:** a restrained white, translucent top bar with bottom border and backdrop blur over the slate-50 admin canvas. Navigation uses small ghost buttons, an outline route to the public explorer, 1rem line icons, and an icon-only Home action with an accessible label. Text labels hide below the small breakpoint (`640px`) while the structure remains usable.

### Tables and Validation
- **Tables:** slate-50 headers, compact uppercase labels, one-pixel row dividers, monospace identifiers, and quiet row hover. Horizontal overflow preserves columns rather than squeezing operational data.
- **Validation:** success and error blocks state whether anything was saved; error tables expose row, field, and actionable message. Atomic failure is visually explicit.

**The Familiarity Rule.** Use the canonical component variant, height, radius, focus, and icon vocabulary across every task; an equivalent action must never acquire a new visual treatment for flavor.

## Do's and Don'ts

### Do:
- Do use semantic UI tokens inside reusable primitives and brand tokens only in deliberately authored brand compositions.
- Do keep operational detail visible with compact `0.75rem`–`0.875rem` type, `1.25rem` card insets, explicit labels, and accessible tables.
- Do state validation, save, replacement, lineage, and publication consequences in text before consequential actions.
- Do pair every success, warning, and error color with wording or an icon, preserve strongly visible keyboard focus, and honor reduced-motion preferences when adding motion.
- Do keep transitions state-driven and brief: the existing vocabulary is `100ms` for overlays and `150ms` for standard color and control feedback.

### Don't:
- Don't resemble a decorative SaaS onboarding wizard.
- Don't use oversized generic cards or ornamental progress effects.
- Don't hide technical detail or create ambiguous partial saves.
- Don't use friendly-sounding copy that obscures validation failures, replacement semantics, lineage, or publication consequences.
- Don't add decorative motion that doesn't convey state, orchestrated page-load sequences, heavy inactive-state color, or gratuitous gradients.
- Don't use inconsistent component vocabulary across screens, display fonts in UI labels, buttons, or data, or reinvent standard affordances for flavor.
- Don't reach for a modal as the first thought; exhaust inline and progressive alternatives first.
